# 学習記録簿 要件定義・設計まとめ（v2.16.0）

## なぜこれが必要か

自分が「何を」・「どれだけ」やったのか可視化するため
やったことに対しどのくらい身についているのかを再確認するため

今までスプシでガントチャート作成とNotionで可視化していたが、見づらさを感じたため

将来的にはAIを入れて、これから取り組むことにどのくらいの時間(期間)がかかるかを予測できるようにしていきたい

## 概要

タスク（チケット）単位で学習を管理し、進捗・学習時間を可視化するWebアプリケーション。
タスクは **親タスク（グループ）** / **子タスク（実作業）** / **孫タスク（ステップ）** の3階層で管理する。
フロントエンドはHTML/CSS/バニラJS、バックエンドはNode.js（Express）、データベースはMySQLで構成するフルスタック構成。

| 画面               | 概要                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| ① ダッシュボード   | 学習状況のサマリーとグラフを表示                                                                    |

### ① ダッシュボード画面

#### サマリーカード（4枚）

| カード         | 表示内容                                                                          | サブテキスト                                                        |
| -------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 期間の学習時間 | 期間トグル（週/月/年/全）と連動した学習時間（時間単位・小数点1桁）                | 先週比 / 先月比 / 前年比 ±N時間（全期間時は「全データの通算」固定） |
| 進捗率         | 全タスクベースの完了率（%）                                                       | 完了 N / 全 N 件                                                    |
| 進行中タスク   | 期間内の「進行中」ステータスのタスク数（v2.11.0：旧「完了タスク」カードから変更） | 完了 N / 全 N 件                                                    |
| 読了書籍       | `completed_count >= total_chapters` かつ `total_chapters > 0` の書籍数            | 読了 / 全 N 冊                                                      |

- サマリーカードの「期間の学習時間」ラベルは期間トグルに連動して「今週の学習時間」/「今月の学習時間」/「今年の学習時間」/「通算の学習時間」と切り替わる
- 学習時間はすべて **時間単位**（分単位ではなく `minutesToHours()` で小数点1桁に変換）で表示する

#### サマリーカードのスタイル（v2.9.0追加・改訂）

過去に作成した静的モックアップ（`learning-management-mockup.html`）のデザインに合わせ、
サマリーカード4枚（期間の学習時間／進捗率／完了タスク／読了書籍）の**見た目のみ**を変更する。
カードの構成・件数・データロジックは変更しない。

- **アイコン**：絵文字ではなく、モックアップと同じ **Lucideスタイルのインラインsvg** を使用する
  - 期間の学習時間: `clock`（時計）アイコン・`.ic-indigo`
  - 進捗率: `trending-up`（折れ線）アイコン・`.ic-amber`
  - 完了タスク: `check-circle`（チェック円）アイコン・`.ic-green`
  - 読了書籍: `book`（本）アイコン・`.ic-indigo`（モックに合わせ、`indigo`を再利用。`violet`は新設しない）
  - アイコンを囲むボックスは `.icon` クラス（36×36px・`border-radius: 10px`・`display: grid; place-items: center`）
  - 色クラスはモックの命名に合わせ `.ic-indigo` / `.ic-amber` / `.ic-green` とする
    （v2.9.0初版で定義した `.summary-card-icon` / `.summary-card-icon--◯◯` 系クラスは廃止）
- **サブテキストのハイライト**：サブテキスト内の数値部分のみ `.sub-highlight` クラスで緑色
  （`var(--color-status-done)`）・太字（`font-weight: 700`）にする
  - 対象：「期間の学習時間」の先週比・先月比・前年比の数値、「進捗率」の完了数、「読了書籍」の読了数
  - 「完了タスク」のサブテキスト（`全 ${totalCount} 件中`）はハイライト対象の数値がモックに存在しないため対象外
- `period-study-sub` / `progress-sub` / `books-read-sub` の更新方法は `textContent` から `innerHTML`
  （テンプレートリテラルで `<span class="sub-highlight">` を含める）に変更する
  - XSS対策：これらの値はすべてアプリ内部で計算した数値（ユーザー自由入力ではない）のため、
    `innerHTML` 使用によるリスクは許容範囲とする

#### 進捗率カードの集計ロジック詳細（v2.16.0：実装に合わせて正確に記載）

- **分母**：全タスク数（`allTasks.length`）。期間フィルタは適用しない
- **分子**：「選択期間の今日と同じ日付・同じ時刻時点」までに完了したタスク数
  - 基準日時（`borderDate`）= 選択期間の年・月 × 今日の日・時・分
  - 例：2026年6月を選択中・今日が28日14:00なら、`2026-06-28 14:00` 以前に完了したタスクを集計
  - `end_date`（実績完了日）をタイムスタンプ比較で判定する
  - `currentPeriod === "all"` のときは全タスクの完了分をそのままカウント
- **前期比**：前週/前月/前年の同じ基準日時点の完了数で同様に算出し、差分（`progressDiff`）をサブテキストに表示
  - 週: `borderDate - 7日`、月: 1ヶ月前の同日、年: 1年前の同日
  - 全期間時はサブテキストを「全データの通算」固定とし比較なし

#### 進行中タスクカードの仕様（v2.11.0追加・旧「完了タスク」カードを変更）

- カードラベルを「完了タスク」から「進行中タスク」に変更する
- メイン数値：期間内タスク（`filteredTasks`）のうち `status === '進行中'` の件数
- サブテキスト：進捗率カードと同じ「完了 N / 全 N 件」パターンとし、`.sub-highlight` クラスで完了数のみ緑色・太字にする
  - 完了数（N）：期間内タスクのうち `status === '完了'` の件数
  - 全件数（N）：期間内タスクの全件数（`filteredTasks.length`）
  - 進捗率カードの完了数は「全タスクベース」、本カードの完了数は「期間内タスクベース」である点が異なる（集計対象が異なるため数値が一致しないことがある。これは仕様）
- アイコン・色クラスは変更しない（`check-circle` アイコン・`.ic-green` をそのまま流用）
- カードの表示位置・件数の取得元（`done-count` / `done-sub` のDOM ID）は変更しない

#### グラフ — レイアウト構成（B案：セクション分割方式）

画面は「学習時間」セクションと「進捗」セクションに分割し、セクション見出し（`.dashboard-section-title`）を表示する。

**学習時間セクション（2カラム）**

| グラフ             | 種類       | 説明                                                                                                                                                       |
| ------------------ | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 日別学習時間       | 縦棒グラフ | 期間内の日別（週→曜日別、月→日別、年→月別、全→年別）学習時間。予定時間（薄アンバー）と実績時間（インディゴグラデーション）の2データセット。単位は時間（h） |
| カテゴリ別学習時間 | 縦棒グラフ | `category_name` でグループ化し `study_time` を合計。期間切り替えと連動。単位は時間（h）                                                                    |

**進捗セクション（3カラム `.charts-row--triple`）**

| グラフ           | 種類           | 説明                                                                                                                   |
| ---------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| ステータス別件数 | ドーナツグラフ | 期間内タスクの未着手/進行中/完了の件数                                                                                 |
| 書籍別進捗率     | 横棒グラフ     | タスク数が1件以上ある書籍のみ表示。`completed_count / task_count` を%表示（0〜100%）。件数に応じて高さを動的計算       |
| カテゴリ別進捗率 | 横棒グラフ     | タスク数が1件以上あるカテゴリのみ表示。`category_name` ごとの完了数/総数を%表示（0〜100%）。件数に応じて高さを動的計算 |

**進捗率推移（全幅）**

| グラフ     | 種類         | 説明                                                  |
| ---------- | ------------ | ----------------------------------------------------- |
| 進捗率推移 | 折れ線グラフ | 予定進捗と実績進捗の2本の累積カーブ。凡例を下部に表示 |

- **予定進捗（%）**: `allTasks`（全期間）を対象に、各ラベル時点（その日付以前）の `end_planned_date` を持つタスク数 / 全タスク数
- **実績進捗（%）**: `allTasks`（全期間）を対象に、各ラベル時点以前の `end_date` を持ち `status === '完了'` のタスク数 / 全タスク数
- 期間種別ごとのラベル日付: 週→各曜日の23:59:59、月→各日の23:59:59、年→各月末の23:59:59、全→最古年1月〜現在月の各月末23:59:59

#### グラフのスタイル

- グラフの高さは動的計算を使用するもの（書籍別・カテゴリ別進捗率）とそれ以外で管理を分ける
  - 書籍別進捗率: `books-wrapper-js` のIDを持つ要素の height を `Math.max(件数 × barHeight, 250)px` で動的計算（件数が6超なら `barHeight=32`、以下なら `45`）
  - カテゴリ別進捗率: `category-wrapper-js` のIDを持つ要素の height を `Math.max(件数 × barHeight, 200)px` で動的計算（同上）
- グラフ軸のテキストカラーは `#aaa`（X軸ラベル）、`#eee`（Y軸ラベル横棒）
- グリッド線カラーは `rgba(255, 255, 255, 0.1)`
- `chartDaily` / `chartCategoryTime` は描画直後に `.resize()` でつぶれ防止する

#### 期間切り替え（v2.12.0：「全」トグルを正式追加）

- **週 / 月 / 年 / 全**（一括切り替え）
  - 切り替えにより棒グラフの軸が変わる（週 → 曜日別、月 → 日別、年 → 月別、**全 → 年別**）
  - サマリーカードも期間に連動して集計が変わる
- 前へ / 次へボタンで期間を移動（未来方向は現在期間まで）
  - **「全」トグル選択時は次へボタンを常時無効化する**（全期間は固定で「次」が存在しない）
- 期間ラベルで現在表示中の範囲を表示（例: "6/8 〜 6/14" / "2026年6月" / "2026年" / **"全期間"**）

##### 「全期間」トグルの挙動詳細

- `currentPeriod === "all"` のとき `filteredTasks = tasks`（全件）を対象に集計する
- サマリーカード「期間の学習時間」：
  - ラベルを「通算の学習時間」に変更（`updateSummaryCardLabel()` で制御）
  - サブテキストは比較対象がないため「全データの通算」固定文字列を表示（ハイライトスパンで囲む）
- 日別学習時間グラフ：タイトルを「年別学習時間」に変更。ラベルはタスクデータから存在する年を昇順で抽出して表示
- 進捗率推移グラフ：最古年の1月から現在月まで月単位のラベル（`YYYY年M月`形式）で累積カーブを描画
- 「全」トグルの `data-period="all"` ボタンが `index.html` に実装済み

#### カテゴリ別集計ロジック

- `filteredTasks`（現在の期間内のタスク）を `category_name` でグループ化
- `category_name` が `null` / 未定義の場合は「(言語不問)」として集計
- タスク数が0件のカテゴリ・書籍はグラフに表示しない
- 配色は `CHART_COLORS` 配列（8色）を書籍別進捗率と共通で使用し、カテゴリ数が多い場合は循環

#### Chart.jsインスタンス管理

- グラフ変数: `chartDaily`, `chartStatus`, `chartBooks`, `chartProgress`, `chartCategoryTime`, `chartCategoryProgress`
- `renderCharts()` の冒頭で全インスタンスを `.destroy()` してから再生成（重複エラー防止）

※ 件数・学習時間の集計はすべて **子タスク（実作業）** を基準とする。

### ② タスク一覧画面

タスクページ上部のタブでビューを切り替える。

#### カンバンビュー（デフォルト）

- カンバン形式（未着手 / 進行中 / 完了の3列）
- カンバンに並ぶカードは「親タスク（グループ）」。親自身はステータスを持たず、
  配置される列は子タスクのステータスから自動算出（ロールアップ）する
  - 子がすべて **当年中に完了**（`end_date` の年が現在年） → 完了列
  - 子がすべて未着手 → 未着手列（子が0件の親もここ）
  - それ以外（進行中あり／ステータス混在／過去年に完了したタスクを含む）→ 進行中列
- 完了列の表示は **当年完了分のみ** にスコープする。過去年に完了したタスクを含む親グループは進行中列に表示される
- 親カードはアコーディオン形式で開閉でき、開くと子タスク（実際の作業）の一覧を表示
  - 子タスク行には種別バッジ・カテゴリバッジ（「(言語不問)」含む常時表示）を表示する
  - 子タスク行には「◯/◯ステップ完了」バッジを表示（ステップが1件以上ある場合）
  - 子タスク行には**ステップ達成率バー**（v2.10.0追加）を表示する（ステップが1件以上ある場合のみ。バッジは廃止せず、バーを追加で表示）
- 親カードのヘッダー直下に**進捗率バー**（v2.10.0追加）を表示する
  - 算出基準：その親グループに属する子タスクの完了数 / 全体数（`calcGroupProgress()`）
  - 子タスクが0件の親グループは進捗率バーを表示せず「－」とする
- ボタン構成（v2.7.0で画面上部の「親タスク追加」ボタンを廃止し、各列ヘッダーの「+」に統一）
  - 各カンバン列ヘッダーの「+」ボタン（`kanban-add-btn`） → 親（グループ）登録モーダルを開く
  - 各親カード内の「子タスク追加」行 → 子タスク登録モーダルを開く（親タスクIDを自動セット）
- 親カードのクリックで親の編集モーダル、子の行のクリックで子の編集モーダルを開く
- カンバン上の親カードの並び順は `groups` の取得順（`sort_order ASC, id ASC`）に従う（本ビューは並び替え機能の対象外）

#### テーブルビュー

- 全グループを縦に並べ、各グループの子タスクをテーブル形式で表示
- グループ行（タイトル・件数・「+」ボタン・編集ボタン）+ 子タスク行（タイトル・種別/カテゴリバッジ・ステータス・予定日・完了日・学習時間・ステップ進捗バッジ・進捗率）
- テーブルに**進捗率カラム**（v2.10.0追加）を新設する。`<thead>` は「タイトル／種別／ステータス／進捗率／予定日／完了日／学習時間／ステップ」の8カラム構成
  - グループ行：そのグループの子タスク完了数 / 全体数（%）をバー＋ラベルで表示。子タスク0件は「－」
  - 子タスク行：紐づくステップの達成数 / 全体数（%）を `table-progress` バーで表示。ステップ0件は「0%」バーを表示する
  - グループ行は `colspan="7"` のタイトルセル＋操作セルの2セル構成（進捗率・操作は右端セルに格納）
- グループ行の右端に「+」ボタンを配置し、クリックで子タスク登録モーダルを開く（`btn-add-task-table`）
- 子タスク行クリックで編集モーダルを開く（モーダル内でステップを管理）
- グループ行のクリックで子タスク行を折りたたみ/展開する（アコーディオン）
  - 折りたたみ状態は `localStorage`（キー: `collapsedTableGroups`、値: 閉じているgroupIdの配列のJSON）で保持する
  - `renderTable()` 実行時に `localStorage` から復元し、閉じているグループの子タスク行を `display: none` に設定する
  - 削除済みの親タスクIDが `collapsedTableGroups` に残存していてもDOMに対応要素がなければ無視される（実害なし）
- **グループの並び順（v2.8.0追加）**：グループの `created_at`（登録日時）**降順**で表示する（新規作成したグループが一番上に来る）
  - `renderTable()` 内で `sortGroupsByCreatedAtDesc(groups)` を呼び出し、ソート済みの配列を描画に使用する
  - カンバン・カレンダー・タイムラインの並び順には影響しない（テーブルビュー固有のソート）

#### カレンダービュー

- 月カレンダー形式で子タスクを表示
- `start_planned_date`（開始予定日）をもとに、各週行のバーレイヤーに帯状の予定バーを表示する
- ← → ボタンで月を移動
- ヘッダーの「+ 子タスク追加」ボタンはv2.7.0で廃止。日付セルの空きスペースをクリックすると
  その日を `start_planned_date` / `end_planned_date` にセットした状態で `openAddTaskGroupPicker()` を呼び出し、
  子タスク登録モーダルを開く（バークリックは編集モーダルの起動が優先され、追加扱いにはならない）
- バークリックで編集モーダルを開く（モーダル内でステップを管理）
- 日付の比較はDateオブジェクトのローカルタイムゾーン（年・月・日）基準で行う

**予定バー・実績バーの2段表示（v2.13.0追加）**

- 各タスクにつき**予定バー（上段）**と**実績バー（下段）**を同一行内に重ねて表示する
- **予定バー**：`start_planned_date` 〜 `end_planned_date` の期間。半透明ホワイト系（`rgba(255,255,255,0.05)` / ボーダー `rgba(255,255,255,0.08)`）。カテゴリバッジ・ステップ進捗バッジを内包する
- **実績バー**：`start_date` 〜 `end_date` の期間。`start_date` が設定されている場合のみ表示。アンバー系（`rgba(245,158,11,0.2)` / ボーダー `rgba(245,158,11,0.45)`）。左端に「実」プレフィックスラベルを付与する。`end_date` がない場合は `start_date` 単日の1日バーとして表示する
- バーの配置ロジック（高さは可変）：
  - 実績バーありのタスク：予定バー 20px + バー間隔 2px + 実績バー 18px + タスク間隔 4px = **44px**
  - 実績バーなしのタスク：予定バー 20px + タスク間隔 4px = **24px**
  - 各タスクの `top` 位置は上から積み上げ計算（固定ピッチではなく可変）
- セル行の高さは `max(110, 28 + バー総高さ + 8)px` で動的に拡張し、バーがセルをはみ出して隣の週と重なることを防ぐ
- 予定バー・実績バーともにクリックで編集モーダルを開く
- CSSクラス：`.calendar-task-bar--planned`（予定）/ `.calendar-task-bar--actual`（実績）

#### タイムラインビュー

- 月単位の横軸ガントチャート形式で子タスクを表示
- 左側にグループ名（140px固定幅）、右側に日付軸とバーを表示する2カラムグリッド構成
- 1行目は日付軸専用の行（1日〜月末までの日付を表示）
- `start_planned_date` 〜 `end_planned_date` の期間を**予定バー**（上段）でで表示
  - 一方のみ設定されている場合、もう一方の値で補い1日分のバーとして表示
  - `end_planned_date` が `start_planned_date` より前の場合は同日として扱う
  - 期間が表示月の範囲外にかかる場合、表示月の範囲にクリップして表示
  - 両方未設定の場合はバーを表示しない（グループ行自体は表示する）
- `start_date` が設定されているタスクは**実績バー**（下段）を予定バーの22px下に追加表示する（v2.13.0追加）
  - `start_date` 〜 `end_date` の期間を表示。`end_date` がない場合は `start_date` 単日の1日バーとして表示する
  - 実績バーの色はアンバー系（`rgba(245,158,11,0.25)` / ボーダー `rgba(245,158,11,0.45)`）
  - 左端に「実 タイトル」のラベルを表示する
  - 予定バー・実績バーともにクリックで編集モーダルを開く
  - CSSクラス：`.timeline-bar--planned`（予定）/ `.timeline-bar--actual`（実績）
- 1タスクにつき行高さ **48px固定**（予定バー上段 20px + 余白 2px + 実績バー下段 18px + 余白 8px）で描画する
  - 実績バーがない場合も48pxを確保する（同一行高さ固定）
  - `calcTimelineBarPosition()` ヘルパー関数でバーの位置（left%・width%）を計算する
- グループ単位で行をまとめ、子タスク数に応じて行の高さを可変にする
- 本日の日付に縦の目印ライン（アンバー色）を表示する（表示中の月が今月の場合のみ）
- ← → ボタンで月を移動
- バークリックで編集モーダルを開く（モーダル内でステップを管理）
- **バーのドラッグ＆ドロップ（日付移動）**：予定バーを別のトラック位置にドロップすると `start_planned_date` を更新して即時API保存する
- **バーのリサイズ（期間変更）**：予定バーの左右端にリサイズハンドル（`.timeline-resize-handle`）を配置し、ドラッグで `start_planned_date` / `end_planned_date` を変更して即時API保存する。変更後は `fetchTaskViewData()` を再実行して再描画する
- 日付軸行の左側セル（グループ名列幅140pxと同じ）に月ナビゲーション（← →ボタン・年月ラベル）を配置する
- 年月ラベルをクリックすると年月ピッカー（`<input type="month">`）が開き、任意の年月に直接ジャンプできる
- ビューパネル上部のツールバー（`.timeline-toolbar`）に「完了タスクを非表示」チェックボックス（`timeline-hide-completed`）のみを配置する
  - 「+ 子タスク追加」ボタン（`btn-add-task-timeline`）はv2.7.0で廃止。タイムライントラックの空きスペースをクリックすると
    クリック位置のX座標から日付を逆算し、その日を `start_planned_date` / `end_planned_date` にセットした状態で
    子タスク登録モーダルを開く（行の親グループが特定できればそのグループIDを自動セット、特定できなければグループ選択モーダルを挟む）
  - チェック時、`status === '完了'` の子タスクをフィルタし、バーおよび親タスク行ごと非表示
  - フィルタ後に子タスクが0件になった親グループ行は描画しない
  - **子タスクが最初から0件の親グループ**については、完了タスク非表示フィルタの対象外とし、グループ行として描画する（カンバンビューとの挙動統一）
- **グループ行の並び順（v2.8.0追加）**：グループ内子タスクが持つ `start_planned_date` のうち**最も早い日付の昇順**で表示する（古い予定日のグループが一番上に来る）
  - `renderTimeline()` 内で `sortGroupsByEarliestPlannedDate(groups, tasks)` を呼び出し、ソート済みの配列を描画に使用する
  - 対象グループに `start_planned_date` を持つ子タスクが1件もない場合（子タスクが0件のグループを含む）、そのグループは日付を持つグループ群の **末尾** に `id` の昇順で配置する
  - 完了タスク非表示フィルタ（`timeline-hide-completed`）のON/OFFに関わらず、並び替えの基準は全子タスク（フィルタ前）の `start_planned_date` を用いる

#### 子タスク追加ボタンの動作（カレンダー・タイムライン共通、v2.7.0で変更）

- `openAddTaskGroupPicker(groups, plannedDate)` 関数を使用
  - グループが1件の場合: 直接その親タスクIDで子タスク登録モーダルを開く（`plannedDate` があれば開始予定日・終了予定日に自動セット）
  - グループが複数の場合: `prompt()` による番号入力をv2.7.0で廃止し、`group-picker-modal`（一覧クリック式のモーダル）を開く。
    一覧から親タスクをクリックすると、その親タスクIDで子タスク登録モーダルを開く

### ③ タスク登録・編集（モーダル）

- 親タスク用・子タスク用の2種類のモーダルを用意
- 親タスクモーダル：タイトル・メモ（・並び順）の登録/編集/削除（「未分類」は削除不可）
  - **子タスクが1件以上紐づいている親タスクは削除不可**（DBの外部キー制約 `ON DELETE RESTRICT` により弾かれる）
  - 削除失敗時はサーバーから返却されるエラーメッセージ（例:「このグループにはタスクが紐づいているため削除できません」）をalertで表示する
- 子タスクモーダル：タイトル・種別・書籍ID・ステータス・開始予定日・終了予定日・
  開始日・完了日・実績学習時間・予定学習時間・メモの登録/編集/削除
  - モーダル下部に**ステップ（孫タスク）セクション**を設ける
    - テキスト入力＋追加ボタンでステップを追加
    - 各ステップにチェックボックス（完了/未完了）と削除ボタン
    - ステップはモーダルを開いたタイミングでAPIから取得して表示
    - **ステップの追加・チェック・削除は即時API通信**で処理される（モーダルの「保存」を待たずに確定する）
    - そのため、ステップの変更はキャンセルや✕ボタンで閉じても元に戻らない（未保存確認ダイアログの対象外）
    - モーダルのDirty判定（`getTaskModalSnapshot()`）のスナップショットにステップ情報を含めているが、
      ステップのみを変更してキャンセルした場合でもダイアログが表示されることがある（既知の挙動・許容範囲内）
  - **ステップ詳細編集エリア（v2.15.0追加）**：各ステップ行の ▼ ボタンをクリックするとインラインでアコーディオン展開し、
    開始予定日・終了予定日・実績開始日・実績終了日・予定学習時間・実績学習時間を入力できる（2×3の6フィールドグリッド）。「保存」ボタンで即時API通信し確定する。
    設定済みの値はステップ行のサブテキストとして表示される（例：📅 6/1〜6/3 / ✅ 実績 6/5〜6/7 / ⏱ 予定 1.0h）。
    保存後は詳細エリアが自動で閉じる。`server/routes/steps.js` のPUT許可フィールドは `start_planned_date`・`end_planned_date`・`start_date`・`end_date`・`planned_study_time`・`study_time`（`actual_date` は廃止）。
  - **ステップ集計の子タスク反映（v2.15.1追加）**：ステップの「保存」またはステップ削除のたびに、
    そのタスクの全ステップの `planned_study_time` / `study_time` を合計し、子タスクの予定・実績学習時間に自動反映する（`syncStepTotalsToTask()`）。
    モーダル内の入力欄もリアルタイムで更新される。
    また、子タスクモーダルのステップセクション下部に「∑ ステップから集計」ボタン（`btn-step-aggregate`）を設置し、
    手動で任意のタイミングで集計を実行できる。
  - 「タスクを追加」から開いた場合は親タスクIDを自動セット
  - 単独で作る場合は親タスク＝「未分類」を初期選択
  - **既存タスクの編集時のみ「複製」ボタンを表示する**（v2.11.0追加）。詳細は次項「子タスクの複製機能」を参照
- いずれもタスク一覧画面上にモーダル表示し、操作はモーダル内で完結

#### 子タスクの複製機能（v2.11.0追加）

似た内容の子タスク（例：「Chapter1」「Chapter2」のような連番タスク）を毎回手入力する手間を減らすため、既存の子タスクから値を引き継いだ新規登録モーダルを開ける「複製」機能を設ける。

- 子タスク編集モーダル（既存タスクを開いた場合のみ）のアクションボタン行に「複製」ボタンを表示する
  - 新規登録モーダル（既存タスクが存在しない状態で開いた場合）には表示しない
  - ボタンは「削除」ボタンと同じ左側グループに配置する（フッターのボタン構成は「削除」「複製」を左、「キャンセル」「保存」を右にまとめる）
- 「複製」ボタンをクリックすると、**DBへの即時保存は行わず**、現在モーダルに入力されている値を引き継いだ状態で新規登録モーダルを開き直す
  - 引き継ぐ項目：種別・カテゴリ・粒度・紐づく書籍・開始予定日・終了予定日・予定学習時間・メモ
  - 引き継がない項目：タイトル（空欄にする）・ステータス（「未着手」に初期化する）・開始日（実績）・終了日（実績）・学習時間（実績）・ステップ（孫タスク）
  - 親タスク（グループ）は元のタスクと同じグループを維持する
- 開いた新規登録モーダルは通常の新規登録と同じ扱いであり、「保存」ボタンを押すまでDBには登録されない。「キャンセル」「✕」で閉じれば複製は確定しない
- 未保存確認ダイアログ（`closeTaskModalWithConfirm()`）は通常の新規登録モーダルと同様に適用される
- `openTaskModal()` に `prefill` 引数を追加して実装（既存の呼び出し箇所への影響なし）

#### 学習時間の単位変換ルール

- DB保存値は **分単位（整数）**
- モーダルの入力・表示は **時間単位（小数点1桁、h）**
- 保存時: `Math.round(parseFloat(入力値) * 60)` で分に変換
- 表示時: `minutesToHours(分) = Math.round((分 / 60) * 10) / 10` で時間に変換
- この変換は `tasks.js` の保存処理・表示処理・スナップショット取得で統一して適用する

#### モーダルのレイアウト

- 子タスクモーダルは画面の縦スクロールを抑えるため、フォーム項目を2カラムのグリッドで配置する
  - タイトル・紐づく書籍・メモは全幅（1カラム分）で表示
  - 種別/ステータス、カテゴリ/粒度、開始予定日/終了予定日、開始日/終了日、
    予定学習時間/学習時間はそれぞれ左右2列に並べる
- 親タスクモーダルはタイトル・メモのみのため、1カラムのまま

#### モーダルの開閉操作

- モーダル右上に ✕ ボタンを配置し、クリックでモーダルを閉じる
- モーダルの外側（オーバーレイ部分）をクリックした場合もモーダルを閉じる
- フッターのボタン構成は「削除」を左端、「キャンセル」「保存」を右側にまとめて配置する
  - 子タスクモーダルでは、既存タスク編集時に限り「削除」の右隣に「複製」ボタンを配置する（v2.11.0追加）
- 編集中の内容に変更があり、保存せずにモーダルを閉じようとした場合、
  「編集の内容は保存されていません。閉じてもよろしいですか？」という確認ダイアログを表示する
  - OKの場合のみモーダルを閉じる。キャンセルした場合は編集状態を維持する
  - 「保存」「削除」が成功した直後は変更なしの状態として扱い、
    その後にモーダルを閉じる際は確認ダイアログを表示しない
- 上記の開閉操作・確認ダイアログは親タスクモーダル・子タスクモーダルの両方に適用する

### ⑥ リザルト画面（v2.16.0追加）

#### 概要

週次・月次・年次の学習サマリーを振り返るレポート画面。期間の境界（週初め・月初め・年初め）に前期間のリザルトを自動ポップアップ表示する機能も備える。

#### ナビゲーション

- サイドバーのメインナビに「リザルト」リンクを追加する（Lucideアイコン: `trophy`）
- ルーティングは `#page-results`。`resultsInitialized` フラグで初回のみ `initResults()` を実行する
- 2回目以降の表示時は、現在アクティブなフィルタータブに合わせてカードの表示状態を復元する

#### リザルトページ（`#page-results`）

- 画面上部にタイトル「リザルト」とフィルタータブ（週・月・年・全）を横並びで表示
  - タブは `.results-filter-tab` クラス。アクティブタブは `.active`
  - 「週」がデフォルトアクティブ。各タブをクリックするとそのタイプのカードのみ表示（他は `display: none`）
  - 「全」タブ選択時はすべてのカードを表示
- 画面中部のカードエリア（`#results-page-body`）に `result-page-card` クラスのカードを縦並びで生成
  - カードには `.result-type-week` / `.result-type-month` / `.result-type-year` クラスを付与しフィルタリングに使用

#### 生成する期間リスト（`generatePastPeriods()`）

- **週次**：直近4週分。月曜〜日曜の週単位で厳密に算出（今週分は含めない）
- **月次**：直近3ヶ月分。各月の1日〜末日
- **年次**：昨年1年間（1/1〜12/31）

#### リザルトカードの表示内容（`buildResultContent()`）

各カードに以下を表示する：

- **ヘッダー**：期間タイプバッジ（週次/月次/年次）＋期間ラベル（例：「6/8 〜 6/14」「2026年5月」）
- **比較ラベル**：「前週との比較」「前月との比較」「前年との比較」（前期データが存在する場合のみ）
- **サマリーカード3枚**：学習時間（h）・完了タスク（件）・進捗率（期間内）
  - 各カードに前期との差分バッジ（`result-diff`）を表示
- **グラフ2枚**：カテゴリ別学習時間（縦棒）・ステータス別件数（ドーナツ）

#### 差分バッジ（`buildDiffBadgeHtml()`）

- 前期比較データが存在する場合に表示
- UP（増加）: アンバー系・上矢印アイコン・クラス `result-diff--up`
- DOWN（減少）: 青系・下矢印アイコン・クラス `result-diff--down`
- STAY（変化なし）: 緑系・横線アイコン・クラス `result-diff--stay`
- 表示フォーマット：`±N（単位）`
- フェードイン＋バウンスアニメーション付き

#### 期間内タスクの絞り込みロジック（`filterTasksByPeriod()`）

- `status === '完了'` のタスク → `end_date` を基準日として判定
- それ以外のタスク → `end_planned_date` または `start_planned_date` を基準日として判定
- 基準日が `startDate` 〜 `endDate` の範囲内に入るタスクを返す

#### 自動ポップアップ（リザルトモーダル）

- アプリ起動時（`app.js` 末尾）に `checkAndShowResultPopup()` を800ms遅延で実行
- 以下の条件を満たす場合にポップアップを表示する：
  - **今日が月曜日**（`day === 1`）かつ先週のリザルトが未表示
  - **今日が1日**（`date === 1`）かつ先月のリザルトが未表示
  - **今日が1月1日**（`month === 1 && date === 1`）かつ昨年のリザルトが未表示
- 表示済みかどうかは `localStorage`（キー: `shownResults`、値: 表示済みIDの配列JSON）で管理する
- 複数のリザルトが保留中の場合は、スライドナビゲーション（`result-modal-nav`）で切り替え可能
- 「リザルトページで見る」ボタン（`btn-result-modal-go-page`）で `#page-results` に遷移してモーダルを閉じる
- モーダルを閉じると全保留リザルトを表示済みとしてマーク（`markResultShown()`）

#### グラフ変数の管理

- モーダル専用: `modalChartBar` / `modalChartDoughnut`
- ページ専用: カードごとに都度 `createBarChart()` / `createDoughnutChart()` を呼び出す
- スライド切り替え時は `modalChartBar.destroy()` / `modalChartDoughnut.destroy()` で先に破棄してから再生成（重複エラー防止）

#### CSS・アニメーション

- 数値カード出現時: `.result-stat-value--anim` → `.result-stat-value--visible` でフェードインアニメーション（`statFadeIn` キーフレーム）
- 差分バッジ出現時: `.result-diff--visible` でフェードイン（`diffFadeIn` キーフレーム）＋アイコンバウンス（`bounceUp`/`bounceDown`）
- 期間タイプバッジの色: 週=インディゴ系 / 月=アンバー系 / 年=グリーン系

```
[ブロック0,0][ブロック0,1][ブロック0,2]
[ブロック1,0][ブロック1,1（中心ブロック）][ブロック1,2]
[ブロック2,0][ブロック2,1][ブロック2,2]
```

各ブロックは3×3の9セルで構成。グリッド全体は9×9=81セル。

| セルタイプ | 座標                                                                                                                                                                         | 個数 | 役割                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | ------------------------------------------------------ |
| 中心テーマ | `(4,4)`（中心ブロックの中心）                                                                                                                                                | 1    | 達成したい大テーマ                                     |
| サブテーマ | 各3×3ブロックの中心 `(1,1)` `(1,4)` `(1,7)` `(4,1)` `(4,7)` `(7,1)` `(7,4)` `(7,7)` ＋ 中央ブロック周囲8セル `(3,3)` `(3,4)` `(3,5)` `(4,3)` `(4,5)` `(5,3)` `(5,4)` `(5,5)` | 16   | 大テーマを支える要素・外側ブロック中心セルと双方向同期 |
| アクション | 上記以外の全セル                                                                                                                                                             | 64   | 具体的なアクション                                     |

#### セルタイプ判定ロジック（v2.12.0：実装に合わせて正確に記載）

`getCellType(r, c)` 関数で以下の順に判定する。

```javascript
function getCellType(r, c) {
  if (r === 4 && c === 4) return "center";
  // 中央ブロック全体（行3〜5・列3〜5）の周囲8セルをsub-centerとして扱う
  if (r >= 3 && r <= 5 && c >= 3 && c <= 5) return "sub-center";
  // 外側8ブロック各中心セルもsub-center
  if (r % 3 === 1 && c % 3 === 1) return "sub-center";
  return "action";
}
```

- 中央ブロックの周囲8セル（`(3,3)` `(3,4)` `(3,5)` `(4,3)` `(4,5)` `(5,3)` `(5,4)` `(5,5)`）は `sub-center` 扱い
- 外側8ブロックの中心セル（`(1,1)` `(1,4)` `(1,7)` `(4,1)` `(4,7)` `(7,1)` `(7,4)` `(7,7)`）も `sub-center` 扱い
- 上記16セルは1対1でペア関係を持ち（`mandalaPairs` 配列で管理）、一方に入力すると他方にリアルタイムで同期される（双方向テキスト同期）

#### サブテーマの双方向同期（v2.12.0：新規記載）

マンダラの設計上、中央ブロック周囲8セルと外側ブロック中心8セルは同じ「サブテーマ」を表す。そのため `onCellInput()` 内でペア先のテキストエリアを即時更新し、かつ `pendingCells` にも追記することで自動保存の対象にする。

```javascript
const mandalaPairs = [
  { center: "3:3", outer: "1:1" }, // サブテーマ1 (左上)
  { center: "3:4", outer: "1:4" }, // サブテーマ2 (上)
  { center: "3:5", outer: "1:7" }, // サブテーマ3 (右上)
  { center: "4:3", outer: "4:1" }, // サブテーマ4 (左)
  { center: "4:5", outer: "4:7" }, // サブテーマ5 (右)
  { center: "5:3", outer: "7:1" }, // サブテーマ6 (左下)
  { center: "5:4", outer: "7:4" }, // サブテーマ7 (下)
  { center: "5:5", outer: "7:7" }, // サブテーマ8 (右下)
];
```

- ペアが見つかった場合のみ同期処理が走る（アクションセルへの入力では同期なし）
- 自動保存タイマー（1秒デバウンス）は自分のセルとペア先のセル両方を `pendingCells` に積んでから起動する

#### セル入力

- 各セルはテキストエリア（`<textarea>`）で自由記述
- Tabキーで左→右→次行の順に次セルへフォーカス移動（`Shift+Tab` で逆順）
- 入力後1秒で自動保存（デバウンス）。保存状態を右上のステータス表示（「保存中…」「✓ 保存済み」）で通知

#### 達成トグル機能

- **アクションセル・サブテーマセル**の右上に小さな達成ボタン（○アイコン）を配置する
  - 通常時は非表示（`.mandala-cell:hover` でのみ表示）
  - 達成済みの場合は常時表示（緑色チェックマーク）
- ボタンをクリックすると達成/未達成をトグルする
  - 達成時: セル背景が緑系に変化、アイコンがチェックマークに変化
  - 未達成に戻す: 元の背景色・アイコンに戻る
- 達成状態は **即時API通信**で `is_completed` フィールドとしてDBに保存する（テキスト自動保存とは独立）
- 中心テーマセル `(4,4)` には達成ボタンを配置しない

#### 進捗バー

- チャート上部に「達成 N / 80（N%）」の進捗バーを表示する
  - 対象は中心テーマセル `(4,4)` を除いた80セル
- 達成トグル操作時に即時更新（APIレスポンスを待たずUIを先行更新）

#### セルへの子タスク紐づけ機能（v2.6.0追加）

- **1つのセルに複数の子タスクを紐づけることができる**
- 紐づけた子タスクのタイトルをセル内に一覧表示する（テキストエリアの下部に小さく表示）
- タスクのステータスバッジ（未着手・進行中・完了）をタイトル横に表示する

**紐づけ操作フロー：**

1. セル内の「＋タスク」ボタン（ホバー時に表示）をクリック
2. 子タスク選択モーダルが開く
   - 全子タスクを親タスク（グループ）ごとにグループ化して一覧表示
   - 既に紐づき済みのタスクはチェック済み状態で表示
   - タイトルでインクリメンタル検索できる
   - チェックボックスで複数選択し「保存」で確定（即時API通信）
3. モーダルを閉じるとセルのタスク一覧が更新される

**紐づけ解除：**

- セル内のタスク表示エリアの各タスク横に「×」ボタンを配置し、クリックで即時解除（即時API通信）

**タスク紐づけの表示：**

- セル内下部のタスクエリアに各タスクのタイトルを縦に並べる
- タイトル横にステータスドット（未着手:グレー / 進行中:インディゴ / 完了:グリーン）を表示
- タスクタイトルをクリックすると子タスク編集モーダルを開く（タスク一覧画面の `openTaskEditModal()` を流用）

#### 一覧・CRUD操作

- **新規作成**: タイトルを入力して「+ 新規作成」ボタン（またはEnterキー）で作成。9×9=81セルを空の状態でDBに一括挿入し、作成後そのマンダラを自動選択して表示する
- **選択**: 一覧のアイテムをクリックしてチャートを切り替える。未保存のテキスト変更がある場合は切り替え前に即時保存する
- **削除**: 一覧の「削除」ボタンをクリック。確認ダイアログ後にマンダラ本体・全セル・全紐づきを削除する（`ON DELETE CASCADE`）
- **タイトル更新**: 現バージョンでは一覧表示のみ（タイトル編集UIは未実装）

チャート下部に色分けの凡例を表示する（中心テーマ / サブテーマ / アクション / 達成済み）。

### ルーティング

`location.hash` 方式を採用。

- URLで状態管理できる
- ブラウザの戻るボタンが使える
- サイドバーのリンクは `<a href="#page-xxx">` の形式
- 各ページは初回表示時のみ初期化（`booksInitialized` / `dashboardInitialized` / `settingsInitialized` / `mandalaInitialized` / `resultsInitialized` フラグで管理）
  - 各 `initXxx()` 内で `document.getElementById(...).addEventListener(...)` のように
    要素取得直後に `addEventListener` を呼ぶ箇所がある場合、対応するHTML要素が
    `index.html` に存在しないと `showPage()` 全体が例外で中断し、
    以後すべてのページ遷移ができなくなる（特定ページでリロード→他ページへ遷移できない不具合の典型例）
  - フラグ変数名は宣言時の名称と設定時の名称を一致させること
  - `initXxx()` 内で要素を取得してイベントを登録する際は、要素の存在を確認してから処理するか、
    対応する要素が `index.html` に存在することを必ず確認すること

### カンバンの描画方針

- 「データから盤面をまるごと作り直す」描画関数を1本用意する
- 親の所属列は保存せず、毎回子のステータス配列から算出する
- カンバン全体の再描画時、開いているアコーディオンの開閉状態を再描画前に記録し再描画後に復元する
- カンバン上の親カードの並び順は `groups` の取得順をそのまま使用する（v2.8.0のグループ並び替え機能の対象外）

#### `calcStatus` の完了判定ロジック（v2.3.0〜）

```javascript
function calcStatus(groupId, tasks) {
  const children = tasks.filter((t) => t.group_id === groupId);
  if (children.length === 0) return "未着手";

  const currentYear = new Date().getFullYear();
  const completedThisYear = (t) =>
    t.status === "完了" &&
    t.end_date &&
    new Date(t.end_date).getFullYear() === currentYear;

  if (children.every(completedThisYear)) return "完了";
  if (children.every((t) => t.status === "未着手")) return "未着手";
  return "進行中";
}
```

### 進捗率バー（v2.10.0追加）

カンバンビュー・テーブルビューに、親グループ単位の進捗率バーとカンバン子タスクカードのステップ達成率バーを追加する。

#### 親グループの進捗率（`calcGroupProgress`）

- 算出基準：その親グループに属する**子タスクの完了数 / 全体数**（％）
- 子タスクが0件の親グループは `null` を返し、表示側は「－」とする

```javascript
function calcGroupProgress(groupId, tasks) {
  const children = tasks.filter((t) => t.group_id === groupId);
  if (children.length === 0) return null;
  const completed = children.filter((t) => t.status === "完了").length;
  return Math.round((completed / children.length) * 100);
}
```

- カンバン：親カードのヘッダー直下に進捗率バーを表示する（`createGroupProgressHtml()`）
- テーブル：グループ行の進捗率カラムにバー＋ラベルを表示する（`createTableProgressHtml()`）。子タスク行は当カラムに「－」を表示する

#### カンバン子タスクカードのステップ達成率バー

- 算出基準：そのタスクに紐づく**ステップの達成数 / 全体数**（％）
- ステップが0件のタスクはバーを表示しない
- 既存の「◯/◯ステップ完了」バッジ（`createStepBadgeHtml()`）は廃止せず、バーを追加で表示する（`createStepProgressBarHtml()`）

```javascript
function createStepProgressBarHtml(steps) {
  if (!steps || steps.length === 0) return "";
  const completed = steps.filter((s) => s.is_completed).length;
  const percent = Math.round((completed / steps.length) * 100);
  return `<div class="task-card-step-progress"><i style="width:${percent}%"></i></div>`;
}
```

- このステップ達成率バーは**カンバンビューの子タスクカードのみ**に表示する（テーブル・カレンダー・タイムラインには表示しない）

#### テーブルの `<thead>` 変更

進捗率カラムの新設に伴い、`<thead>` を「タイトル／種別／ステータス／予定日／完了日／学習時間／ステップ／進捗率」の8カラム構成に変更する。グループ行は `colspan="6"` のタイトルセル＋進捗率セル＋操作セルの3セル、子タスク行・インライン追加行も列数を8列に揃える（インライン追加行の `colspan` は `7` → `8` に変更）。

#### 不具合と修正（v2.10.1）

進捗率バー実装直後、**カンバンビューの親カードをクリックしても子タスク一覧が開閉しなくなる不具合**が発生した。

- **原因**：`bindKanbanEvents()` 内のアコーディオン開閉処理が `header.nextElementSibling.classList.toggle("hidden")` という、DOM上の「次の兄弟要素」に依存した実装になっていた。進捗率バー（`.group-card-progress`）を `.group-card-header` の直後に挿入したことで、`nextElementSibling` が子タスク一覧（`.group-card-children`）ではなく進捗率バーのdivを指すようになり、クリックしても見た目に変化のない要素がトグルされるだけになっていた。
- **修正**：`header.closest(".group-card")` で親カードを取得し、`.querySelector(".group-card-children")` でクラス指定により明示的に対象要素を取得する実装に変更した。これによりヘッダー直後に新たな兄弟要素が追加されても影響を受けない。

```javascript
function bindKanbanEvents() {
  document.querySelectorAll(".group-card-header").forEach((header) => {
    header.addEventListener("click", () => {
      const card = header.closest(".group-card");
      const children = card.querySelector(".group-card-children");
      children.classList.toggle("hidden");
    });
  });
  // ...以下変更なし
```

- **教訓**：`nextElementSibling` ／ `previousElementSibling` など「DOM上の並び順」に依存したセレクタは、将来同じ階層に要素を追加・削除した際に静かに壊れるリスクがある。可能な限り `closest()` ＋ `querySelector()` によるクラス指定の明示的な取得に統一する。

### グループ（親タスク）の並び替え（v2.8.0追加）

ビューごとに異なる並び順を要求するため、`groups` 配列をそのまま描画に使わず、ビュー固有のソート関数を経由してから描画する。**ソートはフロントエンド側で行い、API（`GET /api/groups`）の返却順は変更しない**（カンバンビューが既存の取得順に依存しているため）。

#### `sortGroupsByCreatedAtDesc(groups)` — テーブルビュー用

```javascript
function sortGroupsByCreatedAtDesc(groups) {
  return [...groups].sort((a, b) => {
    const aTime = a.created_at ? new Date(a.created_at).getTime() : 0;
    const bTime = b.created_at ? new Date(b.created_at).getTime() : 0;
    return bTime - aTime;
  });
}
```

#### `sortGroupsByEarliestPlannedDate(groups, tasks)` — タイムラインビュー用

```javascript
function sortGroupsByEarliestPlannedDate(groups, tasks) {
  const withDate = [];
  const withoutDate = [];

  groups.forEach((group) => {
    const dates = tasks
      .filter((t) => t.group_id === group.id && t.start_planned_date)
      .map((t) => new Date(t.start_planned_date).getTime())
      .filter((time) => !Number.isNaN(time));

    if (dates.length === 0) {
      withoutDate.push(group);
    } else {
      withDate.push({ group, earliest: Math.min(...dates) });
    }
  });

  withDate.sort((a, b) => a.earliest - b.earliest);
  withoutDate.sort((a, b) => a.id - b.id);

  return [...withDate.map((entry) => entry.group), ...withoutDate];
}
```

#### セルのテキスト自動保存フロー

1. `textarea` の `input` イベントで `pendingCells` にデータを蓄積（ペア先セルも同時に蓄積）
2. 1秒後に `autoSave()` を実行（デバウンス）
3. `PUT /api/mandalas/:id/cells` に `{ cells: [{ row_index, col_index, content }] }` を送信
4. 保存ステータスを「保存中…」→「✓ 保存済み」と更新

#### セルの達成トグルフロー

1. `.mandala-complete-btn` クリックで UI を即時更新（クラス付け替え・アイコン変更・進捗バー更新）
2. `PUT /api/mandalas/:id/cells` に `{ cells: [{ row_index, col_index, is_completed: 0 or 1 }] }` を送信
3. テキスト自動保存とは独立して即時保存（デバウンスなし）

#### セルへのタスク紐づけフロー（v2.6.0追加）

1. セルの「＋タスク」ボタンクリックで子タスク選択モーダルを開く
2. `GET /api/tasks` で全タスクを取得し、親タスクグループ別に一覧表示
3. `GET /api/mandalas/cells/:cellId/tasks` で現在の紐づき済みタスクIDを取得し、チェック状態を初期化
4. ユーザーがチェックボックスで選択/解除し「保存」をクリック
5. 追加分は `POST /api/mandalas/cells/:cellId/tasks`、解除分は `DELETE /api/mandalas/cells/:cellId/tasks/:taskId` を呼び出す
6. モーダルを閉じ、セルのタスク表示エリアを再描画する

#### マンダラ切り替え時の保存保証

- `loadMandala(id)` 呼び出し時に `pendingCells` が空でなければ `clearTimeout` + `autoSave()` を先行実行してから切り替える
