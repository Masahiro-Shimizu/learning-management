# 学習記録簿 要件定義・設計まとめ（v1.6.0）

## なぜこれが必要か

自分が「何を」・「どれだけ」やったのか可視化するため
やったことに対しどのくらい身についているのかを再確認するため

今までスプシでガントチャート作成とNotionで可視化していたが、見づらさを感じたため

将来的にはAIを入れて、これから取り組むことにどのくらいの時間(期間)がかかるかを予測できるようにしていきたい

## 概要

タスク（チケット）単位で学習を管理し、進捗・学習時間を可視化するWebアプリケーション。
タスクは **親タスク（グループ）** / **子タスク（実作業）** / **孫タスク（ステップ）** の3階層で管理する。
フロントエンドはHTML/CSS/バニラJS、バックエンドはNode.js（Express）、データベースはMySQLで構成するフルスタック構成。

## 機能要件

### 画面構成

| 画面               | 概要                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| ① ダッシュボード   | 学習状況のサマリーとグラフを表示                                           |
| ② タスク一覧       | 親タスクをカンバン・テーブル・カレンダー・タイムラインの4ビューで表示      |
| ③ タスク登録・編集 | 親タスク・子タスク・孫タスク（ステップ）の新規登録・編集・削除（モーダル） |
| ④ 書籍マスタ       | 書籍の一覧・登録・編集                                                     |

---

### ① ダッシュボード画面

- 期間内の学習時間（サマリー表示）
- 完了タスク数・進行中タスク数（サマリー表示）
- 学習時間グラフ（棒グラフ）
- タスク状況・ステータス別件数（円グラフ）
- 書籍別進捗率（横棒グラフ）
- 期間切り替え：週 / 月 / 年（一括切り替え）
  - 切り替えにより棒グラフの軸が変わる（週 → 曜日別、月 → 日別、年 → 月別）
  - サマリーカードも期間に連動して集計が変わる

※ 件数・学習時間の集計はすべて **子タスク（実作業）** を基準とする。
親タスクは入れ物のため集計対象に含めない（二重計上を避ける）。

### ② タスク一覧画面

タスクページ上部のタブでビューを切り替える。

#### カンバンビュー（デフォルト）

- カンバン形式（未着手 / 進行中 / 完了の3列）
- カンバンに並ぶカードは「親タスク（グループ）」。親自身はステータスを持たず、
  配置される列は子タスクのステータスから自動算出（ロールアップ）する
  - 子がすべて完了 → 完了列
  - 子がすべて未着手 → 未着手列（子が0件の親もここ）
  - それ以外（進行中あり／ステータス混在）→ 進行中列
- 親カードはアコーディオン形式で開閉でき、開くと子タスク（実際の作業）の一覧を表示
  - 子タスク行には種別バッジ・カテゴリバッジ（「(言語不問)」含む常時表示）を表示する
  - 子タスク行には「◯/◯ステップ完了」バッジを表示（ステップが1件以上ある場合）
- ボタン構成
  - 画面上部の「グループ追加」ボタン → 親（グループ）登録モーダルを開く
  - 各親カード内の「タスクを追加」行 → 子タスク登録モーダルを開く（親タスクIDを自動セット）
- 親カードのクリックで親の編集モーダル、子の行のクリックで子の編集モーダルを開く

#### テーブルビュー

- 全グループを縦に並べ、各グループの子タスクをテーブル形式で表示
- グループ行（タイトル・件数・編集ボタン）+ 子タスク行（タイトル・種別/カテゴリバッジ・ステータス・予定日・完了日・学習時間・ステップ進捗バッジ）
- 子タスク行クリックで編集モーダルを開く（モーダル内でステップを管理）

#### カレンダービュー

- 月カレンダー形式で子タスクを表示
- `start_planned_date`（開始予定日）が当該日のセルにチップ表示
  - `end_date`（完了日）は表示対象としない（`start_planned_date`のみを基準とする）
- 1セルに表示するチップは最大3件。4件目以降は「+N件」とまとめて表示
- チップにはカテゴリバッジ（「(言語不問)」含む常時表示）・ステップ進捗バッジを表示（ステップが1件以上ある場合）
- ← → ボタンで月を移動
- チップクリックで編集モーダルを開く（モーダル内でステップを管理）
- 日付の比較はDateオブジェクトのローカルタイムゾーン（年・月・日）基準で行う
  （DB上はUTCで保存されているため、文字列の単純な切り出しでは日付がずれる点に注意）

#### タイムラインビュー

- 月単位の横軸ガントチャート形式で子タスクを表示
- 左側にグループ名（140px固定幅）、右側に日付軸とバーを表示する2カラムグリッド構成
- 1行目は日付軸専用の行（1日〜月末までの日付を表示）
- `start_planned_date` 〜 `end_planned_date` の期間をバーで表示
  - 一方のみ設定されている場合、もう一方の値で補い1日分のバーとして表示
  - `end_planned_date` が `start_planned_date` より前の場合は同日として扱う
  - 期間が表示月の範囲外にかかる場合、表示月の範囲にクリップして表示
  - 両方未設定の場合はバーを表示しない（グループ行自体は表示する）
- グループ単位で行をまとめ、子タスク数に応じて行の高さを可変にする
- 本日の日付に縦の目印ライン（アンバー色）を表示する（表示中の月が今月の場合のみ）
- ← → ボタンで月を移動
- バークリックで編集モーダルを開く（モーダル内でステップを管理）

### ③ タスク登録・編集（モーダル）

- 親タスク用・子タスク用の2種類のモーダルを用意
- 親タスクモーダル：タイトル・メモ（・並び順）の登録/編集/削除（「未分類」は削除不可）
- 子タスクモーダル：タイトル・種別・書籍ID・ステータス・開始予定日・終了予定日・
  開始日・完了日・実績学習時間・予定学習時間・メモの登録/編集/削除
  - モーダル下部に**ステップ（孫タスク）セクション**を設ける
    - テキスト入力＋追加ボタンでステップを追加
    - 各ステップにチェックボックス（完了/未完了）と削除ボタン
    - ステップはモーダルを開いたタイミングでAPIから取得して表示
  - 「タスクを追加」から開いた場合は親タスクIDを自動セット
  - 単独で作る場合は親タスク＝「未分類」を初期選択
- いずれもタスク一覧画面上にモーダル表示し、操作はモーダル内で完結

#### モーダルのレイアウト

- 子タスクモーダルは画面の縦スクロールを抑えるため、フォーム項目を2カラムのグリッドで配置する
  - タイトル・紐づく書籍・メモは全幅（1カラム分）で表示
  - 種別/ステータス、カテゴリ/粒度、開始予定日/終了予定日、開始日/終了日、
    予定学習時間/学習時間はそれぞれ左右2列に並べる
- 親タスクモーダルはタイトル・メモのみのため、1カラムのまま

#### モーダルの開閉操作

- モーダル右上に ✕ ボタンを配置し、クリックでモーダルを閉じる
- モーダルの外側（オーバーレイ部分）をクリックした場合もモーダルを閉じる
- フッターのボタン構成は「削除」を左端、「キャンセル」「保存」を右側にまとめて配置する
  - 親タスクモーダル・子タスクモーダルともに同じ配置とする
- 編集中の内容に変更があり、保存せずにモーダルを閉じようとした場合
  （✕ボタン・外側クリック・キャンセルボタンのいずれも対象）、
  「編集の内容は保存されていません。閉じてもよろしいですか？」という確認ダイアログを表示する
  - OKの場合のみモーダルを閉じる。キャンセルした場合は編集状態を維持する
  - 「保存」「削除」が成功した直後は変更なしの状態として扱い、
    その後にモーダルを閉じる際は確認ダイアログを表示しない
- 上記の開閉操作・確認ダイアログは親タスクモーダル・子タスクモーダルの両方に適用する

### ④ 書籍マスタ画面

- Google Books API を使って書籍を検索・登録
- 登録済み書籍の一覧・編集・メモ入力

### ⑤ 設定画面

#### タスク種別管理

- 子タスクの「種別」項目をユーザーが自由に追加・編集・削除できる
- 種別一覧をリスト表示し、各行に「編集」「削除」ボタンを配置
  - 編集はインライン編集方式（クリックでテキスト入力に切り替え、保存/キャンセル）
- 下部のテキスト入力＋追加ボタンで新規種別を追加
- 使用中（子タスクに紐づいている）の種別は削除不可。削除しようとした場合、
  使用件数を含むエラーメッセージを表示する
- 種別は表示色を自動割り当て（種別名から算出したハッシュ値に基づき色クラスを決定）

#### カテゴリ（言語/技術）管理

- 子タスクの「カテゴリ」項目をユーザーが自由に追加・編集・削除できる
- 「タスク種別管理」と同一画面・同一UIパターンで、カテゴリ一覧をリスト表示し、各行に「編集」「削除」ボタンを配置
  - 編集はインライン編集方式（クリックでテキスト入力に切り替え、保存/キャンセル）
- 下部のテキスト入力＋追加ボタンで新規カテゴリを追加
- 使用中（子タスクに紐づいている）のカテゴリは削除不可。削除しようとした場合、
  使用件数を含むエラーメッセージを表示する
- 「(言語不問)」（id=1）は編集・削除不可（消すとデフォルト値が宙に浮くため）
- カテゴリは表示色を自動割り当て（カテゴリ名から算出したハッシュ値に基づき色クラスを決定。
  種別の色クラスとは独立した配色を使用）

## データ構造

### 親タスク（グループ）

| 項目       | 型     | 必須 | 備考                                    |
| ---------- | ------ | ---- | --------------------------------------- |
| 親タスクID | string | ✅   | 自動採番                                |
| タイトル   | string | ✅   | まとめ用の名前。例：「Reactを理解する」 |
| メモ       | string | ー   | 自由記述                                |
| 並び順     | number | ー   | カンバン内の表示順（任意）              |

> ※ 親はステータス・種別・学習時間を持たない。
> ステータスは子から自動算出、学習時間は子の合計を表示するのみ。
> 初期データとして「未分類」を1件用意し、どの親にも属させたくない子はここに入れる。
> 「未分類」は削除不可（消すと子が宙に浮くため）。

### 子タスク（実作業）

| 項目         | 型     | 必須 | 備考                                                                                   |
| ------------ | ------ | ---- | -------------------------------------------------------------------------------------- |
| 子タスクID   | string | ✅   | 自動採番                                                                               |
| 親タスクID   | string | ✅   | どの親に属するか（カンバンに出るのは親のため原則必須）                                 |
| タイトル     | string | ✅   | 例：「useStateを理解する」                                                             |
| 種別         | enum   | ✅   | 本 / 動画 / 記事 / 手を動かす練習                                                      |
| カテゴリ     | number | ー   | 言語/技術カテゴリ。`task_categories`参照（外部キー）。未設定時は「(言語不問)」（id=1） |
| 粒度         | enum   | ー   | 章単位 / トピック単位（子タスクの分類タグとして利用）                                  |
| 紐づく書籍ID | string | ー   | 種別が「本」の場合に選択                                                               |
| ステータス   | enum   | ✅   | 未着手 / 進行中 / 完了                                                                 |
| 開始予定日   | date   | ー   | タイムライン・カレンダーの表示に使用                                                   |
| 終了予定日   | date   | ー   | タイムラインのバー終端に使用                                                           |
| 開始日       | date   | ー   | 実際の作業開始日                                                                       |
| 完了日       | date   | ー   | 実際の完了日。ダッシュボードの集計基準                                                 |
| 実績学習時間 | number | ー   | 分単位                                                                                 |
| 予定学習時間 | number | ー   | 分単位                                                                                 |
| メモ         | string | ー   | 自由記述                                                                               |

### 孫タスク（ステップ）

| 項目       | 型      | 必須 | 備考                                            |
| ---------- | ------- | ---- | ----------------------------------------------- |
| ステップID | number  | ✅   | 自動採番                                        |
| 子タスクID | number  | ✅   | どの子タスクに属するか                          |
| タイトル   | string  | ✅   | 例：「公式ドキュメントのp.30〜50を読む」        |
| 完了フラグ | boolean | ✅   | false: 未完了 / true: 完了（デフォルト: false） |
| 並び順     | number  | ー   | モーダル内の表示順（デフォルト: 0）             |

> ※ ステップはチェックリストとして機能する。日付・学習時間などのフィールドは持たない。
> 子タスクが削除されると紐づくステップも自動削除（ON DELETE CASCADE）。
> 集計（ダッシュボード）の基準は引き続き子タスク。ステップ完了数は集計に含めない。

### 書籍マスタ

| 項目          | 型     | 必須 | 備考                     |
| ------------- | ------ | ---- | ------------------------ |
| 書籍ID        | string | ✅   | 自動採番                 |
| タイトル      | string | ✅   | Google Books APIから取得 |
| 著者          | string | ✅   | Google Books APIから取得 |
| カバー画像URL | string | ー   | Google Books APIから取得 |
| メモ          | string | ー   | 自由記述                 |

### タスク種別マスタ

| 項目   | 型     | 必須 | 備考                                |
| ------ | ------ | ---- | ----------------------------------- |
| 種別ID | number | ✅   | 自動採番                            |
| 種別名 | string | ✅   | 一意。例：「本」「動画」「YouTube」 |
| 並び順 | number | ー   | 一覧表示順（デフォルト: 0）         |

> ※ 子タスクの `種別` は `type_id` として本マスタを参照する（外部キー）。
> 使用中（子タスクに紐づいている）の種別は削除不可（`ON DELETE RESTRICT`）。
> 初期データとして「本」「動画」を登録。

### タスク言語/カテゴリマスタ

| 項目       | 型     | 必須 | 備考                                                     |
| ---------- | ------ | ---- | -------------------------------------------------------- |
| カテゴリID | number | ✅   | 自動採番                                                 |
| カテゴリ名 | string | ✅   | 一意。例：「Java」「Python」「JavaScript」「(言語不問)」 |
| 並び順     | number | ー   | 一覧表示順（デフォルト: 0）                              |

> ※ 子タスクの `カテゴリ` は `category_id` として本マスタを参照する（外部キー）。
> 使用中（子タスクに紐づいている）のカテゴリは削除不可（`ON DELETE RESTRICT`）。
> 初期データとして「(言語不問)」（id=1固定・編集/削除不可）を登録。
> タスク種別（学習形式の分類）とは独立した軸として管理する。

## 技術設計

### 技術選定

| 項目               | 選定                              |
| ------------------ | --------------------------------- |
| フロントエンド言語 | HTML / CSS / JavaScript（バニラ） |
| バックエンド       | Node.js + Express                 |
| データベース       | MySQL（phpMyAdminで管理）         |
| グラフ             | Chart.js（CDN）                   |
| フォント           | Google Fonts（CDN）               |
| CSSフレームワーク  | なし（素のCSS・CSS変数）          |
| ビルドツール       | 不要                              |
| データ永続化       | MySQL（REST API経由）             |

### システム構成

```
フロントエンド (HTML/CSS/JS)
        ↕ fetch() / REST API
バックエンド (Node.js + Express)
        ↕ mysql2
データベース (MySQL / phpMyAdmin)
```

### ルーティング

`location.hash` 方式を採用。

```javascript
const routes = {
  "#dashboard": "page-dashboard",
  "#tasks": "page-tasks",
  "#books": "page-books",
  "#settings": "page-settings",
};

window.addEventListener("hashchange", navigate);
window.addEventListener("DOMContentLoaded", () => {
  navigate();
  initTheme(); // テーマ初期化
});
```

- URLで状態管理できる
- ブラウザの戻るボタンが使える
- サイドバーのリンクは `<a href="#dashboard">` の形式
- 各ページは初回表示時のみ初期化（`tasksInitialized` などのフラグで管理）

### ライト/ダークモード

- サイドバー下部のトグルボタンで切り替え
- `localStorage` に保存し、次回アクセス時も復元
- `data-theme="light"` / `data-theme="dark"` を `<html>` 要素に付与し、CSS変数で色を切り替える

### モーダル

HTMLに事前記述・JSで表示/非表示する方式を採用。親タスク用・子タスク用・書籍用の3種類を用意する。

```html
<div id="task-modal" class="modal hidden">
  <div class="modal-overlay"></div>
  <div class="modal-content">...</div>
</div>
```

- 構造がHTMLで把握しやすい
- イベント管理がシンプル
- `.modal.hidden { display: none; }` でオーバーレイの `display: flex` を上書き
- `.modal` には `z-index` を明示的に指定する（タイムラインのバー等、
  `position: absolute` かつ `z-index` を持つ要素より手前に表示するため）

#### モーダルのレイアウト（子タスクモーダル）

- フォーム項目を `.form-grid` による2カラムグリッドで配置し、縦スクロールを抑える
  - タイトル・紐づく書籍・メモは `.field-full` を付与し全幅表示
  - その他の項目は2項目ずつ左右に並べる
- フッターの `.task-actions` は `justify-content: space-between` とし、
  「削除」を左端、「キャンセル」「保存」を `.task-actions-right` でまとめて右側に配置する
- 親タスクモーダルもフッターのボタン配置は子タスクモーダルと同様にする

#### モーダルの開閉・未保存確認

- 各モーダルの `.modal-content` 右上に `.modal-header` を設け、✕ボタン（`.btn-modal-close`）を配置する
- モーダル要素自身（オーバーレイ部分）のクリックイベントで、クリック対象が
  モーダル要素自身（`e.target.id === "task-modal"` 等）の場合に閉じる処理を呼ぶ
- 開閉のたびに以下の関数で「未保存の変更があるか」を判定する
  - `markXxxModalClean()`：モーダルを開いた直後・保存・削除が成功した直後に呼び、
    現在のフォーム値を `dataset.initialSnapshot` にJSON文字列として保存する
  - `isXxxModalDirty()`：現在のフォーム値のスナップショットと `initialSnapshot` を比較する
  - `closeXxxModalWithConfirm()`：`isXxxModalDirty()` が true の場合のみ
    「編集の内容は保存されていません。閉じてもよろしいですか？」の確認ダイアログを表示し、
    OKの場合のみモーダルを閉じる
- ✕ボタン・外側クリック・キャンセルボタンはすべて `closeXxxModalWithConfirm()` を呼ぶ
- 子タスクモーダルのスナップショットには各入力項目の値に加え、
  ステップ（孫タスク）一覧のタイトル・完了フラグも含める

### カンバンの描画方針

- 子のステータス変更で親の所属列が変わるため、DOMを部分的に動かすのではなく
  「データから盤面をまるごと作り直す」描画関数を1本用意する
- 親の所属列は保存せず、毎回子のステータス配列から算出する（保存しないことでズレを防ぐ）
- カンバン全体の再描画時、開いているアコーディオン（`.group-card-children`）の
  開閉状態を再描画前に記録し、再描画後に復元する（再描画によって展開状態がリセットされないようにする）

### タスクビューの状態管理

- `currentView` 変数でアクティブなビューを管理（`'kanban'` / `'table'` / `'calendar'` / `'timeline'`）
- カレンダー・タイムラインの表示月はそれぞれ `calendarDate`・`timelineDate`（Dateオブジェクト、日付は1日固定）で管理
- タブ切り替え時に `.view-tab` の `active` クラスと `.view-panel` の表示/非表示を切り替える
- `fetchTaskViewData()` で `groups` / `tasks` / `books` / `steps`（`task_id`ごとにグループ化）を一括取得し、
  `renderKanban` / `renderTable` / `renderCalendar` / `renderTimeline` に共通で渡す
  - 取得結果は `lastTaskViewData` に保持し、カレンダー・タイムラインの月移動時にAPIを再取得せず再描画する
- ステップの追加・チェック・削除はモーダルを閉じずに完結させ、
  操作後はカンバンカード・テーブル行のステップバッジのみをその場で更新する
  （`updateCardStepBadge`、ページ全体は再描画しない）
