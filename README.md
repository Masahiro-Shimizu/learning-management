# learning-management

# 学習記録簿 要件定義・設計まとめ

## 概要

タスク（チケット）単位で学習を管理し、進捗・学習時間を可視化するWebアプリケーション。
タスクは **親タスク（グループ）** と **子タスク（実作業）** の2階層で管理する。
フロントエンドはHTML/CSS/バニラJS、バックエンドはNode.js（Express）、データベースはMySQLで構成するフルスタック構成。

---

## 機能要件

### 画面構成

| 画面               | 概要                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| ① ダッシュボード   | 学習状況のサマリーとグラフを表示                                             |
| ② タスク一覧       | 親タスクをカンバンで表示し、子タスクをアコーディオンで開閉（ステータス管理） |
| ③ タスク登録・編集 | 親タスク・子タスクの新規登録・編集・削除（モーダル）                         |
| ④ 書籍マスタ       | 書籍の一覧・登録・編集                                                       |

---

### ① ダッシュボード画面

- 今週の学習時間（サマリー表示）
- 連続学習日数（ストリーク表示）
- 日別学習時間（棒グラフ）
- タスク状況・ステータス別件数（円グラフ）
- 書籍別進捗率（横棒グラフ）
- 期間切り替え：週 / 月 / 年（一括切り替え）

※ 件数・学習時間の集計はすべて **子タスク（実作業）** を基準とする。
親タスクは入れ物のため集計対象に含めない（二重計上を避ける）。

### ② タスク一覧画面

- カンバン形式（未着手 / 進行中 / 完了の3列）
- カンバンに並ぶカードは「親タスク（グループ）」。親自身はステータスを持たず、
  配置される列は子タスクのステータスから自動算出（ロールアップ）する
  - 子がすべて完了 → 完了列
  - 子がすべて未着手 → 未着手列（子が0件の親もここ）
  - それ以外（進行中あり／ステータス混在）→ 進行中列
- 親カードはアコーディオン形式で開閉でき、開くと子タスク（実際の作業）の一覧を表示
- ボタン構成
  - 画面上部の「親タスク追加」ボタン → 親（グループ）登録モーダルを開く
  - 各親カード内の「子タスク追加」ボタン → 子タスク登録モーダルを開く（親タスクIDを自動セット）
- 子タスクのステータス変更は、開いた子の行で行う（ステータス選択）。
  変更すると親の所属列が自動で再計算される
- 親カードのクリックで親の編集モーダル、子の行のクリックで子の編集モーダルを開く

> ※ 旧仕様「各列の[+]でタスク登録・その列のステータスを自動セット」は、
> 親がステータスを持たない設計に変更したため廃止。

### ③ タスク登録・編集（モーダル）

- 親タスク用・子タスク用の2種類のモーダルを用意
- 親タスクモーダル：タイトル・メモ（・並び順）の登録/編集/削除（「未分類」は削除不可）
- 子タスクモーダル：タイトル・種別・粒度・書籍ID・ステータス・予定日・
  完了日・学習時間・メモの登録/編集/削除
  - 「子タスク追加」から開いた場合は親タスクIDを自動セット
  - 単独で作る場合は親タスク＝「未分類」を初期選択
- いずれもタスク一覧画面上にモーダル表示し、操作はモーダル内で完結

### ④ 書籍マスタ画面

- Google Books API を使って書籍を検索・登録
- 登録済み書籍の一覧・編集・メモ入力

## データ構造

### 親タスク（グループ）

| 項目       | 型     | 必須 | 備考                                    |
| ---------- | ------ | ---- | --------------------------------------- |
| 親タスクID | string | ✅   | 自動採番                                |
| タイトル   | string | ✅   | まとめ用の名前。例：「Reactを理解する」 |
| メモ       | string | ー   | 自由記述                                |
| 並び順     | number | ー   | カンバン内の表示順（任意）              |

> ※ 親はステータス・種別・学習時間を持たない。
> ステータスは子から自動算出、学習時間は子の合計を表示するのみ。
> 初期データとして「未分類」を1件用意し、どの親にも属させたくない子はここに入れる。
> 「未分類」は削除不可（消すと子が宙に浮くため）。

### 子タスク（実作業）

| 項目         | 型     | 必須 | 備考                                                   |
| ------------ | ------ | ---- | ------------------------------------------------------ |
| 子タスクID   | string | ✅   | 自動採番                                               |
| 親タスクID   | string | ✅   | どの親に属するか（カンバンに出るのは親のため原則必須） |
| タイトル     | string | ✅   | 例：「useStateを理解する」                             |
| 種別         | enum   | ✅   | 本 / 動画 / 記事 / 手を動かす練習                      |
| 粒度         | enum   | ー   | 章単位 / トピック単位（子タスクの分類タグとして利用）  |
| 紐づく書籍ID | string | ー   | 種別が「本」の場合に選択                               |
| ステータス   | enum   | ✅   | 未着手 / 進行中 / 完了                                 |
| 予定日       | date   | ー   |                                                        |
| 完了日       | date   | ー   |                                                        |
| 学習時間     | number | ー   | 分単位                                                 |
| メモ         | string | ー   | 自由記述                                               |

### 書籍マスタ

| 項目          | 型     | 必須 | 備考                     |
| ------------- | ------ | ---- | ------------------------ |
| 書籍ID        | string | ✅   | 自動採番                 |
| タイトル      | string | ✅   | Google Books APIから取得 |
| 著者          | string | ✅   | Google Books APIから取得 |
| カバー画像URL | string | ー   | Google Books APIから取得 |
| メモ          | string | ー   | 自由記述                 |

## 技術設計

### 技術選定

| 項目               | 選定                              |
| ------------------ | --------------------------------- |
| フロントエンド言語 | HTML / CSS / JavaScript（バニラ） |
| バックエンド       | Node.js + Express                 |
| データベース       | MySQL（phpMyAdminで管理）         |
| グラフ             | Chart.js（CDN）                   |
| フォント           | Google Fonts（CDN）               |
| CSSフレームワーク  | なし（素のCSS・CSS変数）          |
| ビルドツール       | 不要                              |
| データ永続化       | MySQL（REST API経由）             |

### システム構成

```
フロントエンド (HTML/CSS/JS)
        ↕ fetch() / REST API
バックエンド (Node.js + Express)
        ↕ mysql2
データベース (MySQL / phpMyAdmin)
```

### APIエンドポイント一覧

| メソッド | パス              | 内容                             |
| -------- | ----------------- | -------------------------------- |
| GET      | `/api/groups`     | 親タスク一覧取得                 |
| POST     | `/api/groups`     | 親タスク新規作成                 |
| PUT      | `/api/groups/:id` | 親タスク更新                     |
| DELETE   | `/api/groups/:id` | 親タスク削除（「未分類」は不可） |
| GET      | `/api/tasks`      | 子タスク一覧取得                 |
| POST     | `/api/tasks`      | 子タスク新規作成                 |
| PUT      | `/api/tasks/:id`  | 子タスク更新                     |
| DELETE   | `/api/tasks/:id`  | 子タスク削除                     |
| GET      | `/api/books`      | 書籍一覧取得                     |
| POST     | `/api/books`      | 書籍登録                         |
| PUT      | `/api/books/:id`  | 書籍更新                         |
| DELETE   | `/api/books/:id`  | 書籍削除                         |

### ルーティング

`location.hash` 方式を採用。

```javascript
const routes = {
  "#dashboard": "page-dashboard",
  "#tasks": "page-tasks",
  "#books": "page-books",
};

window.addEventListener("hashchange", () => {
  const pageId = routes[location.hash] ?? "page-dashboard";
  document.querySelectorAll(".page").forEach((p) => (p.style.display = "none"));
  document.getElementById(pageId).style.display = "block";
});
```

- URLで状態管理できる
- ブラウザの戻るボタンが使える
- サイドバーのリンクは `<a href="#dashboard">` の形式

### モーダル

HTMLに事前記述・JSで表示/非表示する方式を採用。親タスク用・子タスク用の2種類を用意する。

```html
<!-- index.html に事前記述（例：子タスクモーダル） -->
<div id="task-modal" class="modal hidden">
  <div class="modal-content">...</div>
</div>
```

```javascript
// 表示
document.getElementById("task-modal").classList.remove("hidden");
// 値をセット
document.getElementById("modal-title").value = task.title;
```

- 構造がHTMLで把握しやすい
- イベント管理がシンプル

### カンバンの描画方針

- 子のステータス変更で親の所属列が変わるため、DOMを部分的に動かすのではなく
  「データから盤面をまるごと作り直す」描画関数を1本用意する
- 親の所属列は保存せず、毎回子のステータス配列から算出する（保存しないことでズレを防ぐ）

## 実装順序

### フェーズ1：バックエンド基盤

1. `server/schema.sql`（親タスク・子タスク・書籍テーブル定義／「未分類」初期データ／phpMyAdminで実行）
2. `server/db.js`（MySQL接続設定）
3. `server/server.js`（Expressサーバー起動確認）
4. `server/routes/groups.js`（親タスクCRUD API・未分類の削除ガード）
5. `server/routes/tasks.js`（子タスクCRUD API）
6. `server/routes/books.js`（書籍マスタ API）

### フェーズ2：フロントエンド

7. `public/index.html`（骨格・ナビ・全セクション・モーダル）
8. `public/css/style.css`（共通・変数・レイアウト）
9. `public/js/api.js`（fetchラッパー・API呼び出し共通化）
10. `public/js/app.js`（ルーティング）
11. `public/js/tasks.js`（カンバン・親子アコーディオン・ロールアップ算出・モーダル）
12. `public/js/books.js`（書籍マスタ・Google Books API）
13. `public/js/dashboard.js`（グラフ・集計）
14. 各画面のCSS（dashboard / tasks / books / modal）
